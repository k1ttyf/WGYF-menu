# Инструкции для AI-ассистентов

Этот файл является проектными инструкциями для Codex-подобных AI-ассистентов. Перед изменениями прочитайте его полностью.

## Назначение проекта

Проект содержит BepInEx 5 Mono-плагин `CasinoMenu` для игры Gamble With Your Friends. Целевая игровая сборка использует Unity Mono, Mirror и новый Unity Input System.

Основной исходный файл — `src/CasinoMenuPlugin.cs`. Скрипт сборки — `build.ps1`. Результат сборки — `dist/CasinoMenu.dll`.

## Рабочий процесс

1. Сначала изучите существующий код и соответствующие типы в `Assembly-CSharp.dll` из установленной игры.
2. Вносите минимальные изменения в `src`, не редактируйте собранную DLL вручную.
3. После изменений запускайте из корня проекта:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\build.ps1
   ```

4. Считайте задачу выполненной только после успешной компиляции без ошибок. Предупреждения устаревших Unity API допустимы, если они не вызваны новой логикой.
5. Если Windows не разрешает запись в `Program Files`, сообщите путь к `dist/CasinoMenu.dll` и оставьте пользователю ручное копирование от имени администратора.

## Правила реализации

- Сохраняйте совместимость с Unity Mono и версиями библиотек, на которые ссылается `build.ps1`.
- Серверные действия должны проверять `NetworkServer.active`, если их вызов требует host/server.
- Не подменяйте сетевую игровую логику локальным состоянием без необходимости.
- Для выдачи предметов используйте canonical-список `Resources.Load<SpawnableSettings>("SpawnableSettings").spawnables`; наличие prefab обязательно.
- `ItemManager.ServerAddItem` только обновляет список предметов. Для появления объекта в мире нужны `Instantiate(prefab, position, Quaternion.identity)` и `NetworkServer.Spawn`.
- Скорость noclip является множителем базовой скорости из `PlayerSettings`, а не абсолютным числом units/sec. Не ломайте этот смысл при изменении движения.
- Для ввода учитывайте Unity Input System и текущие переназначаемые клавиши проекта.
- Не добавляйте сетевой автообновлятор или внешний endpoint без явного требования пользователя.
- Не изменяйте файлы игры в `Program Files` как часть исходного кода; используйте `dist` и штатную установку из `build.ps1`.

## Проверка изменений

Проверяйте изменённые функции в собственной offline/host-сессии. После загрузки игры смотрите `BepInEx/LogOutput.log`. Минимальный набор проверок для функций движения и предметов:

- включение и выключение noclip;
- соответствие скоростей `x0.5`, `x1` и `x10` базовой скорости игрока;
- создание предмета перед локальным игроком;
- отсутствие ошибок Harmony, Mirror и `MissingMethodException` в логе.

Не тестируйте серверные чит-функции в чужих публичных сессиях.

## Стиль изменений

- Сохраняйте существующий стиль C# и понятные имена методов.
- Не удаляйте рабочие функции ради упрощения без согласования.
- Не добавляйте зависимости, которых нет в `build.ps1`.
- В итоговом сообщении указывайте изменённые файлы, результат сборки и известные ограничения установки или тестирования.
